## Workflow completato

Ho recuperato il materiale del corso clonando il repository pubblico del docente in una cartella separata all'interno di ~/workspace, mantenendolo distinto dal mio repository personale per evitare conflitti tra gli aggiornamenti del corso e il mio lavoro. Ho poi creato il repository azure-devops-lab sul mio account GitHub, impostandolo come pubblico, e l'ho clonato localmente nel filesystem Linux di WSL, verificando con `git remote -v` che puntasse correttamente al mio account. Ho invitato il docente come collaboratore direttamente dalle impostazioni del repository. Dopo aver preparato la struttura con le cartelle evidenze e laboratori, ho usato `git status` per controllare quali file risultassero nuovi o modificati prima di ogni operazione, così da non aggiungere nulla per errore. Ho selezionato con `git add` solo i percorsi specifici di questa evidenza, evitando un'aggiunta indiscriminata dell'intera cartella, poi ho verificato con `git status` cosa fosse effettivamente in staging. Ho quindi creato il commit con `git commit` e messaggio descrittivo, e ho concluso con `git push` per pubblicare il lavoro sul repository remoto, autenticandomi tramite il flusso browser di Git Credential Manager configurato in precedenza.
